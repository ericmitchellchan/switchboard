# Switchboard

## Project Overview
Personal workstation desktop app: tabbed terminal multiplexer for AI coding agent sessions (split panes, PTY management, agent status detection, auto-task extraction) plus route-switched Knowledge Base, diagram, and repo Explorer screens with durable agent threads, and a per-tab artifact panel that keeps a doc/wireframe/diagram/repo file co-present with the running shell. Built with Tauri v2 + React 18 + xterm.js v5.

## Conventions

- **THE PAGE TOOLS CAN DROP MID-SESSION, AND THE HEADER SAYS SO (SWIT-113, 2026-09-30 — the platform review: on Sep 24 a gamma thread lost its page/view tools after a model switch and only the agent noticed)** — the SWIT-65 chip knew only what `prepare_thread_launch` said at launch. The MCP server now writes `threads/<id>/mcp.json` at boot (`{version:1, pid, startedAt}`), stamps `endedAt` when its stdin closes — ONLY while the record is still its own pid (a `/mcp` reconnect's newer server owns the file) — and RE-ASSERTS its record every 20s (`MCP_REASSERT_MS`) if another server took it over, so a short-lived second server that ended cannot leave a false end behind. Rust's `thread_mcp_health` (`mcp_health.rs`, pure `judge` tested) reads the record and the pid's creation time + running flag through one handle (`jobs::process_facts`): `none` (no record — an older server, or not booted: NO CLAIM, the SWIT-65 rule) · `alive` (running, created ≤ 2 s after and ≤ 120 s before the server's own `startedAt`, so a recycled pid never counts) · `ended` · `gone`. App's 5s pass asks it for every LIVE thread whose launch prepared, and `lib/toolsHealth.nextToolsVerdict` (pure) is the rule: only a record that started at or after this launch (`ThreadPrepared.at`, stamped at every prepared launch, − 5 s skew) speaks; `ended`/`gone` must last `DROP_AFTER_MS` (30 s, longer than the re-assert) before the prep record becomes `{prepared:false, dropped:true, reason: TOOLS_DROPPED_REASON, at}`, and `alive` again (a reconnect) restores `{prepared:true, at}`. A real prep failure or an outside conversation is never touched (`healthLaunchAt`). The chip is the SAME `PrepChip`: `page tools dropped`, its title saying to type `/mcp` in claude, a click relaunching through the revive path (the confirm dialog's copy says the same). Stated: claude exiting to its shell (`/exit`) also ends the server, so the chip shows on a thread whose claude was quit on purpose — the click is the right fix there too. NOT VERIFIED IN THE APP: the server write, the Rust judgement and the rule are tested; a real model switch dropping the tools is the check.
- **A REPORT BECOMES A FINDING IN ONE CLICK (SWIT-114, 2026-09-30 — the one-platform mock's Ask scene: "A report you trust becomes a finding in one click, so it outlives the thread")** — `components/views/FindingAction.tsx`: a `→ finding` button in a REPORT's toolbar and in a standalone view's (never a drilled child or an embedded block — they file from their report; never a frozen kept view), opening a small card fixed under the button (the toolbar is one clipped line): the claim (prefilled with the view's title, `draftClaim`), the four verdict pills (default lead), an optional n, `File` / `Cancel`, a status line naming the page it lands on. WHERE (`lib/userFindings.findingTargetFor`, pure): a thread's view → that thread, report `view:<id>`; a project view → the thread that BUILT it (the project index row's `threadId`) while it exists, else the thread beside the panel, report `view:<project>/<id>`; no thread anywhere → no button. ONE WRITER PER FILE: page.json's findings stay the agent's; the user's go to the thread's `findings.json` through Rust (`user_findings.rs`: `add_thread_finding` validates claim/verdict/n/report with the agent's caps, refuses control characters, mints `user-<n>` — one past the highest present — newest first, REFUSED at 60, never evicted; `remove_thread_finding` takes off a `user-` id only), and `findings.json` is the seventh `THREAD_FILES` name (read + stamp). The merge (`pageStore.parseUserFindingsFile` + `mergePage`'s fifth argument) joins them to the agent's ledger newest first, marked `by: "user"`, through every reader — the page's poll, `threadDigest` (so Home's Findings and the lane page get them) — and the page draws a dim `you` before the claim and a hover `×` (the evidence `×`'s class and in-flight slot) on the user's rows only. THE AGENT: `page read` (and the lane read's sibling findings) lists them marked `(filed by the user)` (`withUserFindings`, read-only); `op finding` REFUSES a `user-` id by name, and the tool description says those are the user's to keep. NOT VERIFIED IN THE APP: the card's position at panel widths and the round trip to Home are the first things to drive.
- **A STALE REPO-FILE TAB THAT IS REALLY A KB DOC HEALS ITSELF (2026-09-30 — Eric, on 0.18.0: "I can't see the artifact (the MD file) here and the HTML over there")** — a KB doc opened under the pre-SWIT-101 resolver (created after the cached KB list loaded) was saved as `{kind:"repo-file", project, path}` and the workspace restores a tab's kind as written, so the fix never reached it: `cannot resolve "…\switchboard\switchboard\features\…" (os error 3)` on every restart. `ArtifactSurface`'s `RepoFileBody` now, on a read that failed as MISSING (`evidenceModel.isMissingFileError`: os error 2/3), asks `kb.resolveWithFreshKbDocs` (one refresh on a miss) and, when `kbDocForMissingRepoFile` says the path IS a KB doc, draws that doc at once and calls `panelStore.replaceArtifactEverywhere(repo-file, kb-doc)` — every strip (set members included), the toggle memory, the preview mark + back stacks and the floating record — so the next workspace save persists the right kind (audited `artifact-healed`). The source is taken at PARSE time from the banner (`SOURCE_MARKERS` — `VITE v`/`Next.js`/`webpack-dev-server`/`Compiled successfully` vs `Uvicorn running on`/`Starting development server at`/`Serving Flask app` vs `Serving HTTP on`) and travels with the URL; nothing downstream re-sniffs a URL, and PORT HEURISTICS ARE DELIBERATELY NOT USED (8000 is uvicorn's default AND python http.server's). Unknown outranks a known api because we KNOW an api frames as JSON and we do not know that about a one-off, which is also what keeps acceptance 6 true. Evidence is graded: a marker on the URL's OWN LINE beats one on an earlier line, which is load-bearing rather than fussy — the 512-char tail re-shows a URL in the next chunk, and without the grading a preceding vite banner classified the backend label line as `frontend` across the chunk seam. Ties break toward the LATER sighting (a retried port is the settled one). The chip shows `+N` and the `+` picker lists every known URL with its source, so a candidate that lost the chip is one keystroke away instead of a URL you must retype.
- **THE OFFER FOLLOWS THE SHELL, INCLUDING INTO THE PANEL** (2026-08-02) — a panel terminal renders `TerminalPane` ALONE; there is no `SessionHeader` in the panel, and the offer chip lives on the header. So a `pnpm dev` started in the panel — which is exactly where Eric runs them — was detected and stored (`noteDevServerOutput` hangs off the registry's per-session output hook, which does not care what is mounted) and then had NOWHERE TO APPEAR: the URL existed only in the `+` picker's detected list, findable if you already knew to look. `DevServerOffer` is therefore EXPORTED from SessionHeader and rendered by App's `renderPanelSession` as a sibling above the terminal — the same component, so the frame-not-open wording, the `+N` sibling count and the dismissal rule cannot drift into a second implementation. It returns null with no offer, so it costs no layout until there is something to say, and the height change when one appears is a pane move like any other — nothing resizes (SWIT-103). **AND IT IS `framed` THERE, NOT `compact`** — shipped as `compact` first, which is the DENSEST variant (9px, 2px padding) built for a cramped split-pane header, dropped straight onto scrollback in the one host with no chrome of its own. Eric's verdict was “the chip is kinda hidden” and he was right: in a pane the chip sits inside SessionHeader's bar, in the panel it is the ONLY route to the preview and has to announce itself. `framed` gives it its own row (elevated background, hairline beneath), full size, primary text and the localhost globe; it still renders only alongside a real offer, so an idle shell costs no layout — a wrapper in the HOST would have left a permanent empty bar. The chip targets `getActiveTabSession()`, so the preview lands in the TAB's strip beside the terminal rather than inside the terminal's own (non-existent) panel
- **ONE SERVER, ONE IDENTITY — `localhost` and `127.0.0.1` are two spellings, not two servers** (2026-08-02, a real bug with a real receipt in `%LOCALAPPDATA%/switchboard/scrollback`) — one `pnpm dev:web`, one vite, two announcements: the dev script prints `[lodestar] desktop -> browser http://localhost:5273` on spawn and vite prints `➜ Local: http://127.0.0.1:5273/` ~2s later. Every layer compared URL STRINGS, so the second announcement looked like a server nobody was looking at: it was not in `known` (a second candidate), `isLocalhostUrlOpen` said no (the chip came back for a server already framed), and `artifactIdentity` differed (the click appended a SECOND tab for the SAME vite). The fix is a COMPARISON KEY, `devServer.serverKey`, used by all three (`noteDevServerOutput`'s dedupe, `panelStore.isLocalhostUrlOpen`, `artifactIdentity`'s localhost arm) — the detector's answer and the strip's answer have to agree or a URL that was not offered twice can still open twice. It folds ONLY the loopback host (`localhost`/`127.0.0.1`/`[::1]`/`0.0.0.0`/`[::]` → one token); scheme, port and PATH stay, because a path is a ROUTE and a localhost artifact names one (positional pins are scoped to it). The URL is still framed VERBATIM — `normalizeMatch` deliberately does not rewrite a specific loopback address, since a server bound only to IPv4 loopback is reachable at `127.0.0.1` for certain while `localhost` bets on the resolver (lodestar's vite config pins `host: "127.0.0.1"` for exactly that reason). What DOES move is which spelling a known server carries: an `unknown` sighting upgraded by a real banner adopts the banner's ADDRESS as well as its source, because a tool states what it actually bound and a hand-written label line states what its author assumed — and a candidate is only ever REWRITTEN, never added, so an offer already taken or dismissed cannot come back. HONEST LIMIT: two processes really can bind one port separately on 127.0.0.1 and [::1], and this key calls those one server; that is rarer than one dev script announcing itself twice, which is every full-stack dev script
- **The preview names the OTHER servers as DOTS, never as tabs** — Eric: *"It'd be nice to have the backend thing there too just because we know what's actually alive. It's not kind of ghost running."* The ranking already decides which server gets framed (the frontend); the rest get one line of the preview toolbar — `● api 127.0.0.1:8799` — probed with the SAME no-cors check the frontend's own dot uses, and clicking one frames it as a fallback rather than as the default (an API renders as JSON or a 404, which tells you less than the dot does). The join is BY URL, not by session id (`devServer.siblingServersFor`): LocalhostView is handed an artifact, not a session — it renders in whichever tab's panel holds it and in the floating window, which has no session at all — so the URL is looked up in the announcement store instead of threading a session id through two hosts and a pop-out. A URL nothing announced (typed into `+`) has no siblings, which is the honest answer. **And the wording never says "healthy"**: a no-cors probe resolves when something accepted the connection and rejects when nothing is listening, and the response is OPAQUE, so a 500 and a 200 are indistinguishable from here. The tooltip says "listening — something accepted the probe" / "not answering — nothing is listening on that port" and states outright that it is not a health check
- **The live preview's root is a FLEX ITEM, and that is why it carries `flex: 1; min-width: 0`** (measured 2026-08-02) — LocalhostView's `ROOT_STYLE` was copied from WireframeView, where the identical style is correct because that root is a BLOCK child of DocView's scroller and a block box fills its container for free. `ArtifactSurface`'s localhost arm wraps its child in `display: flex`, so the same style set meant something different: without `flex-grow`, `flex-basis: auto` resolved to the item's max-content width, and an `<iframe>` is a REPLACED element whose intrinsic width is 300px whatever `width: 100%` says. Two consequences, both deliberate: a pin marks a place ON SCREEN rather than in the document (scroll the app and the badge stays put — the recorded `viewport` is what keeps the note interpretable), and IN-APP navigation is invisible to us (`contentWindow.location` throws), so pins are scoped to the URL the ARTIFACT names and the rail SAYS which route that is instead of pretending to follow along. Per-DOCUMENT (artifact identity, like the zoom key — a repo file and a KB doc can share a path) and per-SESSION (sessionStorage, write-through at the moment of change, never an effect keyed on [identity, collapsed] — that clobbers the stored value on a doc switch, the recorded bug). Collapsed is a real 26px clickable edge, never nothing: a rail that vanished would take its own toggle with it
- **The floating window hosts EITHER a terminal or an artifact — one window lifecycle, not a second window type** — `pip.html?session=` mirrors a shell (as always); `pip.html?artifact=<json>` hosts an artifact, and `pip:host` re-aims a window that is ALREADY open rather than closing and recreating one that is on screen. It renders the same `ArtifactSurface` the panel renders, so a popped-out wireframe keeps its pins and a popped-out preview keeps its overlay and health card. While an artifact is out there the panel tab shows a PLACEHOLDER, not a second live copy — two frames on one dev server, two health polls and two mounts of one pin sidecar is duplication, not co-presence — and closing the window (its `x`, Ctrl+Shift+O, or `back`) returns it. PiP finally has discoverable entry points too: the panel header's `float` action and the status bar's `Ctrl+Shift+O float`
- **An invoke that did not come from the app's own document does not run — and the ONE-CALL-SITE mitigation is gone** — increment F measured that Tauri injects `__TAURI_INTERNALS__` into every frame, so a framed page with `allow-same-origin` could `invoke("write_file")` and a file appeared on disk. The only defence was the sandbox attribute at ONE call site, which meant any future frame anywhere silently re-opened full command access including `create_session` (process execution). `src-tauri/src/ipc_guard.rs` is the durable fix: the invoke handler is WRAPPED, and an invoke whose `Origin` is not one of the app's own document origins is rejected and logged before any command sees it. The allowlist is built ONCE at setup from the app's own config (`tauri.localhost` in all three production forms + `build.devUrl`, the latter ONLY under `tauri::is_dev()` so a shipped bundle cannot hand IPC to port 1620); per-invoke `Webview::url()` is a blocking UI-thread round trip and `write_to_session` runs on every keystroke. `plugin:`/`core:` commands never reach the handler and never needed to — tauri ACL-gates them to `ExecutionContext::Local` because `capabilities/default.json` declares no `remote` URLs; the hole was that the APP's own commands skip the ACL entirely when the app declares no ACL manifest (`has_app_acl_manifest`, tauri 2.10.2 `webview/mod.rs`). MEASURED, both directions, with a probe (a cross-origin `allow-scripts allow-same-origin` frame): frame custom-protocol `kb_root`/`write_file` → REJECTED, no file; frame `window.ipc.postMessage` with the REAL invoke key → NO RESPONSE; main frame → RESOLVED on both transports.
- **An ABSENT `Origin` is a different TRANSPORT, not an unknown caller** — tauri has two IPC paths and only the custom-protocol one carries headers. `ipc-protocol.js` switches PERMANENTLY to `window.ipc.postMessage` the first time a fetch rejects, which is exactly what a page UNLOAD does to in-flight requests: Switchboard's `beforeunload` flush (`save_scrollback`, `save_threads`) arrives with no Origin at all. Denying it would drop the workspace save on every F5 — data loss dressed as security — so `classify()` returns `PostMessage` (allow) for an absent header and `Deny` for a header that is present and wrong (`null`, a framed origin). That is only safe because a subframe cannot REACH that transport, which was measured: wry registers `ICoreWebView2::add_WebMessageReceived`, which WebView2 raises for the TOP-LEVEL document only (iframes raise `CoreWebView2Frame::WebMessageReceived`, unregistered). Windows/WebView2 only — re-run the probe before trusting this branch on another platform.
- **Explicit save, and never a silent overwrite in either direction** — `lib/editor.ts` owns the whole rule set and `MarkdownSurface` only draws it. Ctrl+S is the ONLY writer (a ~1s autosave would put Eric and an agent on overlapping timers over one file — the exact race that produced two data-loss bugs in the pins layer). `foldDisk` reconciles disk against buffer on every host read: a CLEAN buffer FOLLOWS the file (the existing 2500ms poll, unchanged), a DIRTY one raises a CONFLICT and touches neither side until keep-mine / take-theirs. Save re-reads FIRST and turns a moved file into the same banner — that is the only way a REPO file, whose host does one-shot reads and never polls, can notice an external change. A failed write KEEPS the buffer and shows the error; the one path that loses typed text is a `discard` button. Dirty buffers survive tab/screen/artifact switches AND a restart (localStorage mirror, debounced 400ms, flushed synchronously on `beforeunload` and on the close dialog, which also SAYS they are kept). The ONE case where a repo file polls is an OPEN EDIT BUFFER (`useRepoFile(project, path, pollMs)`, driven by `useHasBuffer`): a KB doc's 2500ms poll already raises the banner under a dirty buffer, and a repo file must do it at the same speed rather than waiting for Ctrl+S. Loading policy stays the HOST's — the editor store only answers "is there a buffer".
- **Repo markdown is editable, and the guard is the read guard plus two rules** — `explorer_write` runs `resolve_repo_rel` (layer 1: component-wise validation of the RAW relative path — no `..`, no absolute/drive/verbatim/UNC form, no `:` in a component — then the canonical repo root) and `canonicalize_within` (layer 2: containment, which is what closes the junctioned-parent hole), exactly as `explorer_read` does. Then: the file must ALREADY EXIST (an editor saves, it does not drop new files into a source tree — and `fs::canonicalize` requiring existence is what makes layer 2 cover the FINAL component here, unlike `kb_write_doc`, which needs an extra `symlink_metadata` check because it creates), and a symlink at the target is refused outright. Roots are never client-supplied: a write addresses a repo by registry KEY. Cargo tests mirror the kb.rs guard tests, junction case included.
- **Markdown is the only editable kind** — `isEditable` = `docKind === "markdown"` AND a file-backed artifact. Wireframes, diagrams, `.jsx/.tsx` previews and live localhost frames stay READ-ONLY; the edit surface is reached through the SAME `ArtifactBody` kind switch, so it appears in the panel, on both full-width screens and in the PiP window without any host knowing about it. The buffer is keyed by `artifactIdentity`, not path — a repo file and a KB doc can share a relative path, and a buffer must never follow you to a different document.
- **One back stack, and it is the store's** — `route.ts` has carried `history` + `navigateBack()` since T4 with nothing consuming them. `BackButton` (rendered on the full-width screens, and only when there is somewhere to go) is that missing half, and `navigate` now DEDUPES the same location so an entry means a real change of place — a back button that returns you to where you are standing is a broken button. `writeRouteToUrl` deliberately still `replaceState`s: mirroring into `pushState` would give the webview's Alt+Left a second, independent stack, and App's popstate handler resyncs by calling `navigate`, so the two would drift apart within a few navigations. Going back to the terminal restores the artifact panel by construction — the panel is per-TAB state in `panelStore`, which navigation never touches. `open full` is an ICON now (the shared `open` mark), because the words were the widest thing in a 36px header on a 260px panel.
- **ONE VISUAL VOCABULARY, AND NO NARRATION IN THE UI** (SWIT-57, 2026-09-01, Eric on the first live question tab: "why are there all these different boxes? … why do we need this narration in the actual UI?") — every shell surface composes from `design/wireframe-kit/components.md` (band header · list row · button · input + textarea · chip · question block · page sections · tooltip, lifted from Ky's desktop components in our tokens). The `? question` tab is the reference: question · options as a plain keyboard-walkable list · one textarea · one quiet `answer`

## Project surfaces (platform evolution — SWIT-28, 2026-08-26)

The decision: **Switchboard is the shell; other apps' UIs come in as PROJECT SURFACES.** A `surface` artifact is `{project, page}` — a project's own React page rendered in THIS document (never an iframe), fed by that project's backend over HTTP/WS. First project: Lodestar (`src/projects/lodestar/`, backend on :8799). Specs: `personal-kb/switchboard/features/platform-evolution/`.

- **A surface is a chunk, not a dependency.** The shell reaches a page only through `surfaces/registry.ts`'s `import()`. Nothing under `src/projects/**` is imported statically anywhere — that is what keeps the terminal registry out of a page's HMR update chain (a save in a page replaces that chunk's modules only; the PTYs live in Rust; the keep-alive root re-adopts xterm elements). Verified empirically as the Inc 1 gate — re-verify if a page ever grows a static import from the shell.
- **The data plane never crosses Tauri IPC.** A surface fetches its backend directly (`127.0.0.1:8799`); the backend sends CORS headers for the webview's origins (`localhost:1620` in dev, `tauri.localhost` packaged). No Vite proxy, no IPC relay — which is also why the Tauri-vs-Electron question is second-order for this app.
- **SurfaceHost owns what a page cannot:** a per-page crash boundary (a throwing chart must not take the doc beside it), the backend card (probe `<url><health>` while ACTIVE, two consecutive misses → a card naming project + URL + a prose hint; Switchboard still never starts servers), and the `.sb-surface` token scope. The root paints TRANSPARENT and takes its host's value — the same rule as every other viewer.
- **Tailwind is for surfaces only, and ships without preflight.** `styles/surfaces.css` imports the utilities + theme layers; the shell's chrome stays hand-written CSS and must never be re-toned by a reset. `@theme` maps a project's token names (`bg`/`surface`/`line`/`text`/`dim`…) onto the zinc ramp where structural and keeps them literal where functional (`up`/`dn`/`liq`/`accent`). One typeface: every `--font-*` is the JetBrains Mono stack.
- **Copied code loses its window.** A page that listened on `window` (keys, resize) in its home app now sits beside a live xterm; scope such listeners to the surface (TradeDetail's arrow keys moved onto a focusable overlay for exactly this reason). `window.lodestar`-style shell bridges do not exist here — the HUD returns as a second Tauri window, not a dead button.
